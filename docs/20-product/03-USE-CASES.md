# P3 — حالات الاستخدام وتدفقات العمل (Use Cases & Flows)

> تجمع: 10 تدفقات `s-acm-master/FLOWS.md` + UC-* من `s-acm/04-use-cases.md` + تدفقات V2 (Quiz/Enrollment) + تدفقات جديدة (Tenant/DSAR). كل تدفق يتحوّل إلى سيناريو Playwright في `docs/50-quality/01-TESTING-STRATEGY.md`.

## UC-TEN — المستأجرون
**UC-TEN-001 إنشاء جامعة جديدة (Super Admin):** يدخل Super Admin → "المستأجرون" → إنشاء: الاسم، النطاق الفرعي، بريد مدير النظام، الخطة → النظام ينشئ المستأجر، ينسخ الأدوار الأربعة النظامية بصلاحياتها، ينشئ مستخدم `TENANT_ADMIN` غير مفعّل، يرسل رابط تفعيل → يُسجَّل في تدقيق المنصة.
**UC-TEN-002 تحديد المستأجر عند الزيارة:** زائر يفتح `ksu.scam.app` → middleware يحلّ المستأجر من host → صفحة الدخول تظهر بشعار الجامعة → بعد الدخول، الجلسة تحمل `tenantId` → أي طلب لاحق بـ host مختلف يُرفض ويُخرج المستخدم.

## UC-AUTH — المصادقة
**UC-AUTH-001 تسجيل الدخول:** بريد/رقم أكاديمي + كلمة مرور → تحقق Zod → البحث ضمن المستأجر فقط → Argon2 verify → فحص الحالة (نشط؟ مفعّل؟ مجمّد؟) → عدّاد الفشل/القفل → إنشاء جلسة (كوكي HttpOnly) → تدقيق `auth.login` → توجيه حسب الدور. الفشل: رسالة موحّدة "بيانات غير صحيحة" دون تحديد السبب.
**UC-AUTH-002 تفعيل الحساب:** رابط بريدي بـ token (24h) → `/activate/[token]` → تعيين كلمة مرور (سياسة) → تفعيل → دخول تلقائي.
**UC-AUTH-003 استعادة كلمة المرور:** `/forgot-password` بريد → (دائماً "إن وُجد الحساب أرسلنا") → OTP 6 أرقام (10 دقائق، 5 محاولات) → `/verify-otp` → `/reset-password` → إبطال كل الجلسات → تدقيق.
**UC-AUTH-004 تسجيل الخروج:** إبطال الجلسة الحالية (أو كلها من "الجلسات النشطة").

## UC-USR — المستخدمون
**UC-USR-001 إضافة مستخدم:** نموذج (اسم، بريد، دور، تخصص/مستوى للطالب) → توليد رقم أكاديمي → إنشاء غير مفعّل → إرسال تفعيل → تدقيق.
**UC-USR-002 تعديل:** فحص `user.edit` + لا يمكن تعديل من يملك صلاحيات أعلى → حفظ → تدقيق (diff).
**UC-USR-003 حذف ناعم:** `deletedAt` → يختفي من القوائم → يظهر في سلة المحذوفات → استعادة أو حذف دائم بعد 30 يوماً.
**UC-USR-004 استيراد SIS:** رفع CSV/XLSX → التحقق من الأعمدة → Dry-run يُظهر (جديد/تحديث/خطأ لكل صف) → تأكيد → job خلفي → تقرير نهائي قابل للتنزيل → إشعار للمدير.
**UC-USR-005 ترقية جماعية:** اختيار التخصص + المستوى الحالي → معاينة الأسماء → تأكيد → تحديث المستوى + تدقيق.

## UC-ROL — الأدوار
**UC-ROL-001 إنشاء دور:** اسم + وصف → مصفوفة الصلاحيات مجمّعة (فئة/مورد/إجراء) مع "تحديد الكل" لكل فئة → لا تظهر إلا الصلاحيات التي يملكها المانح → حفظ.
**UC-ROL-002 تعديل صلاحيات دور:** كما أعلاه؛ الأدوار النظامية للقراءة فقط.

## UC-ACD — البنية الأكاديمية
**UC-ACD-001 إعداد الجامعة لأول مرة (Wizard):** كليات → أقسام → تخصصات → مستويات → السنة الأكاديمية والفصل الحالي. يُقترح تلقائياً عند أول دخول للمدير إن كانت البنية فارغة.

## UC-CRS — المقررات والشُعب
**UC-CRS-001 إضافة مقرر:** رمز + اسم + تخصصات + مستوى + ساعات.
**UC-CRS-002 فتح شعبة:** مقرر + فصل + مدرس(ين) + سعة → حالة "مفتوحة".
**UC-CRS-003 تسجيل الطلاب:** يدوي (بحث وإضافة)، جماعي (كل طلاب تخصص/مستوى)، أو استيراد.

## UC-FIL — الملفات
**UC-FIL-001 رفع ملف:** اختيار شعبة/مقرر + نوع + ملفات → فحص الحجم والنوع (client) → رفع → فحص magic bytes (server) → حفظ بمسار `tenant/course/uuid` → حالة (منشور أو "بانتظار الموافقة" حسب إعداد المستأجر) → إشعار للطلاب عند النشر.
**UC-FIL-002 معاينة/تنزيل:** فحص `file.view` + نطاق (مسجّل في الشعبة) → رابط موقّع 5 دقائق → عارض داخلي أو تنزيل → عدّاد تنزيلات.
**UC-FIL-003 الموافقة:** قائمة "بانتظار الموافقة" → معاينة → قبول/رفض بسبب → إشعار للرافع.

## UC-QUZ — الاختبارات (من V2)
**UC-QUZ-001 إنشاء اختبار:** إعدادات → أسئلة (يدوي أو من البنك أو AI كمسودة) → معاينة → نشر → إشعار للطلاب.
**UC-QUZ-002 أداء الاختبار:** فحص التسجيل + النافذة الزمنية + المحاولات → بدء (مؤقّت خادمي) → حفظ تلقائي لكل إجابة → إرسال أو انتهاء الوقت → تصحيح آلي → نتيجة حسب إعداد العرض.
**UC-QUZ-003 التصحيح اليدوي:** قائمة المقالي → درجة + تعليق → نشر الدرجات → دفتر الدرجات يتحدث.

## UC-GRD — الدرجات
**UC-GRD-001 دفتر الدرجات:** أعمدة تلقائية من الاختبارات/الواجبات + يدوية → أوزان → النهائي → تصدير CSV → الطالب يرى صفّه فقط.

## UC-NTF — الإشعارات
**UC-NTF-001 إرسال:** عنوان + محتوى + أولوية + المستلمون (الكل/دور/كلية/تخصص/مستوى/شعبة/أفراد) → معاينة عدد المستلمين → إرسال → `NotificationRecipient` لكل مستلم → قنوات حسب التفضيلات → المرسل يرى إحصاء القراءة.

## UC-AI — الذكاء الاصطناعي
**UC-AI-001 تلخيص ملف:** اختيار ملف → استخراج نص (PDF/DOCX/PPTX) → إخفاء البيانات الشخصية → فحص الحصة → إرسال للمزوّد → ملخص بحالة "مسودة" وشارة AI → المدرس يعتمد/يحرّر/يرفض → نشر للطلاب (اختياري) → `AIUsageLog`.
**UC-AI-002 توليد أسئلة:** كما أعلاه → أسئلة إلى بنك الأسئلة بحالة مسودة.
**UC-AI-003 محادثة مع المحتوى:** سياق = نص الملف (مقطّع) → أسئلة/أجوبة → سجل محادثة.

## UC-RPT — التقارير
**UC-RPT-001 لوحة المدير:** إحصائيات (مستخدمون، مقررات، ملفات، AI) + رسوم نمو + آخر الأنشطة (كما في لقطة الشاشة المرجعية) — من DB حقيقية.
**UC-RPT-002 تصدير تقرير:** فلاتر → PDF/XLSX على الخادم → تنزيل.

## UC-SYS — النظام
**UC-SYS-001 سلة المحذوفات:** تبويبات (مستخدمون/أدوار/مقررات/ملفات) → استعادة/حذف دائم/تفريغ الكل (تأكيد مزدوج) → تدقيق.
**UC-SYS-002 سجل التدقيق:** فلترة (مستخدم، إجراء، كيان، تاريخ) → تفاصيل diff → تصدير.

## UC-PDP — حماية البيانات
**UC-PDP-001 "بياناتي":** المستخدم يطلب تصدير → job → ملف JSON/PDF بكل بياناته (ملف شخصي، تسجيلات، درجات، إشعارات، سجل AI) → رابط موقّع 24h.
**UC-PDP-002 طلب محو:** المستخدم يطلب → يظهر لمسؤول DSAR → مراجعة (قيود قانونية: سجلات أكاديمية تُحفظ) → إخفاء الهوية (anonymize) بدل الحذف الصلب → إغلاق الطلب موثّقاً.
**UC-PDP-003 حادثة أمنية:** مسؤول يسجّل الحادثة → عدّاد 72 ساعة → تحديد المتضررين → قالب إبلاغ SDAIA → إخطار المستخدمين → إغلاق.
