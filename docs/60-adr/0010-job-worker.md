# ADR-0010 — تنفيذ المهام الخلفية: worker مستقل بقفل صفّي + مسار inline احتياطي (P1-12)

- **الحالة:** مقبول — 2026-09-30
- **السياق:** جدول `Job` موجود منذ P1-01 (`type, status, payload, attempts, maxAttempts, runAt, lockedAt, lockedBy`)، وثلاثة أنواع تُنفَّذ فعليًا (`notification.fanout` من P1-07، `trash.purge` من P1-08، `mail.send` من P1-11) لكن **كلها inline** عبر `after()` داخل عملية Next بعد الرد. هذا لا يعيد المحاولة بعد انهيار، ولا يعمل لمهام مجدولة (`runAt` مستقبلي)، ولا يتوسع أفقيًا، ويُحمّل خادم الويب عمل البريد والتنظيف. المعمارية (`00-ARCHITECTURE.md`) نصّت منذ البداية على worker من نفس الكود.
- **القرار:**
  1. **بروتوكول قفل واحد لكل المشغّلات:** كل معالج (`processMailJob`, `processFanoutJob`, `purgeExpired`) يمتلك القفل بنفسه: `updateMany({ where: { id, status: "PENDING", type }, data: { status: "RUNNING", lockedAt, lockedBy, attempts++ } })` — إن أعاد 0 فالصف ليس لنا. ثم يسجّل `SUCCEEDED` أو يُعيده `PENDING` (للمحاولة التالية) أو `FAILED` عند `attempts >= maxAttempts`. المعالجات مسجّلة في **`lib/jobs/registry.ts`** (`JOB_PROCESSORS: type → fn(tenantId, jobId, workerId)`) — مصدر وحيد للتوزيع.
  2. **الـworker (`src/worker/index.ts`, `pnpm worker`)** عملية Node مستقلة من نفس الكود (`tsx --conditions=react-server` كي تُحلّ `server-only` إلى الفارغ كما في RSC). حلقة: **حجز** دفعة `PENDING` بـ`runAt <= now()` و`lockedBy IS NULL` عبر `UPDATE … FROM (SELECT … FOR UPDATE SKIP LOCKED) RETURNING` بدور المالك (`platformPrisma` — يقرأ صفوف `Job` فقط عبر المستأجرين، لا بيانات مستأجر)، ثم توزيع بتزامن `WORKER_CONCURRENCY`، والمعالج يفعل القفل الحقيقي ويعمل تحت RLS عبر `tx(tenantId)`. **حاصد**: `RUNNING` أقدم من `WORKER_STALE_LOCK_MINUTES` → `PENDING` (المحاولة محسوبة) أو `FAILED` إن نُفدت المحاولات؛ حجوزات معلّقة تُحرَّر. إيقاف رشيق على SIGINT/SIGTERM (ينتظر الجاري ≤ 30 ث).
  3. **المسار inline يبقى كاحتياط صريح** (`lib/jobs/kick.ts → kickJob(tenantId, jobId, type)`): مع `JOBS_INLINE=true` (الافتراضي — تطوير/معاينة/عقدة واحدة بلا worker) يُشغَّل المعالج بعد الرد عبر `after()`؛ مع `JOBS_INLINE=false` يكتفي الطلب بالإدراج. **تشغيلهما معًا آمن** لأن القفل الشرطي يمنع التنفيذ المزدوج (مُختبَر في `tests/integration/worker.test.ts`).
  4. **البريد الحقيقي:** `lib/mail` يحصل على ناقل `smtp` (nodemailer، `SMTP_HOST/PORT/USER/PASSWORD/SECURE`، مهلات صريحة، singleton على `globalThis`). محليًا Mailpit (`docker-compose.yml`: `db` + `mailpit`؛ الواجهة `:8025`). الاختبار التكاملي يرسل عبر SMTP ويتحقق من الوصول عبر Mailpit REST API؛ يُتخطّى تلقائيًا إن لم يكن Mailpit يعمل (يُسجَّل ذلك في الأرقام).
  5. **لا Redis/BullMQ الآن:** الحجم المتوقع (مئات المهام/دقيقة لكل عملية) يخدمه PostgreSQL بـ`SKIP LOCKED` بلا خدمة إضافية؛ الفهرس `(status, runAt)` موجود. إن احتجنا طوابير عالية الإنتاجية (AI في P2) يُضاف broker بقرار جديد دون تغيير عقد `Job`.
- **البدائل المرفوضة:** (أ) BullMQ/Redis — خدمة إضافية وحالة خارج القاعدة بلا حاجة حالية؛ (ب) `pg_cron`/`LISTEN/NOTIFY` — يقيّد مزوّد القاعدة ويعقّد الاختبار؛ (ج) إزالة inline كليًا — يجعل التطوير والمعاينة يعتمدان على عملية ثانية ويكسر e2e الذي يقرأ روابط البريد من `Job.result` فورًا.
- **العواقب:** `JOBS_INLINE`, `WORKER_*`, `SMTP_*` في `env.ts`؛ `docker-compose.yml` جديد؛ `scripts/restart-server.sh` لا يشغّل worker (اختياري)؛ AGENTS §2 يشرح التشغيل؛ `Job.lockedBy` يُستخدم كحجز (قيمة `hostname#pid#rand`)؛ `enrollment.import` و`export.tenant` يُضافان إلى السجل عند بنائهما (P2-06/P3-07).
