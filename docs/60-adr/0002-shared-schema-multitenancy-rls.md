# ADR-0002 — تعدد المستأجرين بمخطط مشترك + tenant_id + Postgres RLS

- **الحالة:** مقبول — 2026-09-04
- **السياق:** البيع لعدة جامعات يتطلب عزلاً مضموناً بتكلفة تشغيل معقولة وSuper Admin طبيعي. البحث في `docs/10-research/01-MULTI-TENANCY.md`.
- **القرار:** جدول `Tenant`؛ `tenantId` على كل جدول؛ `ENABLE + FORCE ROW LEVEL SECURITY` بسياسة `current_setting('app.current_tenant_id', true)`؛ Prisma Client Extension تضبط GUC بنطاق المعاملة؛ دور DB للتطبيق بلا `BYPASSRLS`؛ اتصال منفصل بدور مميز لصفحات المنصة فقط؛ تحديد المستأجر من host ومطابقته بالجلسة.
- **البدائل:** DB لكل مستأجر (مرفوض كافتراضي؛ يبقى خياراً لـ "استضافة خاصة")؛ Schema لكل مستأجر (Prisma لا يدعمه جيداً).
- **العواقب:** انضباط في الفهارس المركبة والـ FK المركبة؛ اختبار عزل مولَّد لكل موديل؛ يتطلب Postgres حقيقياً (لا SQLite) حتى في الاختبار.
