# R3 — الامتثال التنظيمي السعودي: PDPL و NCA ECC وحوكمة AI

> **لماذا:** الجامعات السعودية (عامة وخاصة) خاضعة لنظام حماية البيانات الشخصية (PDPL) ولضوابط الهيئة الوطنية للأمن السيبراني (NCA). أي مورّد نظام يجب أن يُثبت دعم هذه المتطلبات تقنياً. (البيع لجامعات خارج السعودية: نفس الأدوات تغطي GDPR تقريباً.)

## 1. نظام حماية البيانات الشخصية (PDPL)

| البند | ما يعنيه للنظام | الميزة في scam2027 | ID |
|---|---|---|---|
| نافذ منذ 14 سبتمبر 2024 (بعد سنة سماح) | الامتثال إلزامي الآن | — | — |
| الجهة: SDAIA | تسجيل المتحكمين | حقل `TenantCompliance.controllerRegistrationNo` | PDPL-01 |
| حقوق أصحاب البيانات: العلم، الوصول، التصحيح، المحو، نسخة من البيانات | DSAR | صفحة "بياناتي" للمستخدم: تصدير JSON/PDF، طلب تصحيح، طلب محو؛ لوحة DSAR للمسؤول بمهلة (30 يوماً) | PDPL-02 |
| الموافقة/الأساس القانوني | تسجيل الموافقات | `Consent { userId, purpose, grantedAt, revokedAt, version }` + شروط الاستخدام المُصدَّرة | PDPL-03 |
| الإشعار بالخصوصية | قبل الجمع | صفحة سياسة خصوصية لكل مستأجر (قابلة للتحرير) + قبول عند أول دخول | PDPL-04 |
| سجل أنشطة المعالجة (RoPA) | توثيق الأغراض والفئات والمدة | `ProcessingActivity` مُدار من مسؤول المستأجر + قالب مُعبّأ مسبقاً للسيناريو الأكاديمي | PDPL-05 |
| تقليل البيانات والاحتفاظ | حذف عند انتهاء الغرض | `RetentionPolicy` لكل نوع بيانات (سجلات تدقيق، ملفات، خريجون) + job تنفيذ | PDPL-06 |
| الإبلاغ عن الخروقات خلال **72 ساعة** لـ SDAIA + إخطار المتضررين | سجل خروقات | `BreachIncident` (وقت الاكتشاف، الأثر، الإجراءات، وقت الإبلاغ) + عدّاد 72 ساعة + قالب إبلاغ | PDPL-07 |
| مسؤول حماية البيانات (DPO) | جهة اتصال | حقول DPO في المستأجر + ظهور في سياسة الخصوصية | PDPL-08 |
| النقل خارج المملكة | يحتاج أساساً (SCC/BCR أو استثناءات) | إعداد "مزوّد AI" لكل مستأجر مع تحذير إن كان خارجياً + خيار عدم إرسال بيانات شخصية للـ AI (إخفاء الأسماء) + توثيق منطقة استضافة DB | PDPL-09 |
| تصنيف البيانات (4 مستويات) | عام/مقيّد/سري/سري للغاية | حقل `classification` على `File` وحقول شخصية موثّقة في `02-DATA-MODEL.md` | PDPL-10 |
| العقوبات حتى 5 ملايين ريال | مخاطر الجامعة | يبرّر جعل PDPL جزءاً من P2/P3 وليس "لاحقاً" | — |

## 2. NCA — الضوابط الأساسية للأمن السيبراني ECC-2:2024

4 مجالات، 28 مجالاً فرعياً، 108 ضوابط رئيسية. ما يمس المنتج مباشرة:

| المجال الفرعي | الضابط في scam2027 |
|---|---|
| 2-2 إدارة الهويات والصلاحيات | RBAC بالحد الأدنى من الامتيازات، MFA للمديرين، مراجعة دورية للصلاحيات (تقرير "من يملك ماذا") |
| 2-3 حماية الأنظمة | تحديث التبعيات، تعطيل الميزات غير المستخدمة |
| 2-5 أمن الشبكات | TLS، CORS مقيّد |
| 2-7 حماية البيانات | تشفير أثناء النقل والتخزين، تصنيف |
| 2-8 التشفير | خوارزميات معتمدة، إدارة مفاتيح |
| 2-9 النسخ الاحتياطي | نسخ لكل مستأجر + اختبار استعادة موثّق |
| 2-10 إدارة الثغرات | `npm audit` + Dependabot + فحص دوري |
| 2-11 اختبار الاختراق | وثيقة نطاق + سجل نتائج (خارج الكود) |
| 2-12 السجلات والمراقبة | سجل تدقيق، احتفاظ ≥ 12 شهراً، حماية من التعديل |
| 2-13 إدارة الحوادث | سجل حوادث (يشترك مع PDPL-07) |
| 4-1 الأمن السيبراني للأطراف الثالثة | العقود/الاتفاقيات — مسؤولية المورّد، لكن النظام يوفّر تقارير الامتثال |

## 3. حوكمة الذكاء الاصطناعي (SDAIA AI Ethics Principles + إرشادات الذكاء الاصطناعي التوليدي)

| المبدأ | التطبيق |
|---|---|
| الشفافية | كل مخرج AI يحمل شارة "مولّد بالذكاء الاصطناعي" + إخلاء مسؤولية |
| الإشراف البشري | ملخصات/أسئلة AI في حالة `draft` حتى يعتمدها المدرس |
| الخصوصية | إزالة/إخفاء الأسماء والأرقام قبل الإرسال لمزوّد خارجي؛ خيار مزوّد محلي |
| المساءلة | `AIUsageLog` (من، ماذا، متى، أي نموذج، كم رمزاً، التكلفة) |
| العدالة | لا استخدام AI في قرارات درجات نهائية آلياً |
| الحدود | حصص لكل مستأجر/مستخدم، تحديد نماذج مسموحة |

## 4. إخراج الامتثال (Compliance Pack) للجامعة

النظام يولّد للمسؤول: (1) تقرير RoPA، (2) تقرير الصلاحيات، (3) تقرير DSAR المفتوحة/المغلقة، (4) تقرير الحوادث، (5) تقرير سجل التدقيق لفترة، (6) إثبات النسخ الاحتياطي الأخير — كلها PDF/CSV.
